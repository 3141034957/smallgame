# 乐队账号与单账号单会话登录（免密）

## 使用方式

账号只认昵称，**不设密码**。首次进入即可游客游玩，账号栏和单局结算提供「登录」入口，输入昵称就能进入乐队：服务端没有这个昵称时，用你当前游客进度创建它；已有该昵称时，直接返回它的云端存档，本次带去的游客进度被忽略，不会覆盖。换设备输入同一昵称即可继续。

账号（昵称）为 3–32 位英文字母、数字或下划线，不区分大小写（统一按小写规范化）；不含空格、控制字符和其他 Unicode 字符。没有「确认输入」这一步，也没有登录/注册切换：两个入口行为完全一致。

**安全取舍（有意如此，需知悉）**：昵称就是全部凭据，任何人输入他人昵称即可使用该昵称的存档，没有任何二次校验可以拦住；昵称被他人占用后也没有自助找回手段。因此昵称不应包含手机号、真实姓名、邮箱等敏感信息，也不应在游戏中绑定现实身份。服务端剩余的防护只有限流、CSRF/同源校验和会话机制（见下文），**不再有凭据校验这一步**。换取的是零门槛进入、换设备即续玩、不保存也无法泄露任何密码。

同一账号只有一个有效会话。成功进入会立即使该账号之前的会话失效；昵称格式不对、被限流或服务忙碌不会踢掉当前会话；不同账号互不影响。同浏览器的多个标签页共享 Cookie，账号改变后会同步重新检查。页面每 15 秒、重新获得焦点和变为可见时检查会话；上榜接口立即拒绝无效会话。刷新可保持登录，会话绝对有效期为 7 天。退出登录由服务端删除当前会话，不只是隐藏页面。

首次进入某个新昵称（相当于注册）自动继承本机游客时期累计的全部金币、已拥有及当前选择的角色、永久强化、任务、成就、生涯、昵称、设置与最佳成绩。账号、游客快照及会话在同一数据库事务中创建，创建失败不会清掉游客记录，成功后保留当前结算页和游戏状态。游客快照另存本机备份，再开始独立的新游客存档，避免重复转移同一份金币。进入已有昵称优先恢复云端，游客存档单独保留。切换账号和退出先卸载旧游戏，再切换存档作用域，避免迟到写入混到其他账号。

账号和会话保存在服务器 SQLite，重启后保留。游戏成长进度保存到服务器 SQLite，刷新或换设备登录可恢复。登录后的本机改动延迟 500 ms 合并上传，同一账号串行同步；断网时保留本机待同步标记，联网和页面恢复时重试。上传途中发生的新改动会在确认上一版后继续上传，旧版本不能覆盖更新的云端进度，重复请求可安全重试。发生冲突时可恢复云端，未上传的本机副本另行备份。匿名旧排行榜记录保留，但客户端不能通过提交匿名 ID 认领它们。

账号弹窗使用与战场一致的奶油色、草地绿背景，并复用角色表中的鼓手咚咚、吉他手弦弦和主唱啾啾透明 WebP。游客态顶栏只有一个「登录」按钮；弹窗标题为「输入昵称，进入乐队」，只有一个昵称输入框，提示语为「3–32 位字母、数字或 _ · 不设密码，换设备输入同一昵称即可继续」，按钮为「进入乐队」，成功后提示「已进入，进度已同步」。手机隐藏外围装饰角色，表单可纵向滚动；关闭后回到游戏，战斗中打开账号表单会暂停。

## 接口与存储

| 接口                      | 用途                                                                      |
| ------------------------- | ------------------------------------------------------------------------- |
| `POST /api/auth/register` | `{ account, progress? }`，进入乐队（与 login 行为完全一致，保留仅为兼容） |
| `POST /api/auth/login`    | `{ account, progress? }`，进入乐队，替换旧会话                            |
| `GET /api/auth/session`   | 返回当前 `{ user: { id, username } }`，无 Cookie 时 `user: null`          |
| `POST /api/auth/logout`   | 删除当前会话并清 Cookie                                                   |
| `GET /api/progress`       | 返回当前账号 `{ data, revision }` 成长快照                                |
| `POST /api/progress`      | `{ data, revision }`，按预期版本更新，版本冲突返回 409                    |

写请求必须使用 JSON 和 `X-Echo-Request: 1`。页面携带 `X-Echo-User` 防止旧标签页将对局写到新登录的账号。服务不开放跨域 CORS；前后端通过同一 IP 和端口提供，接口使用相对 `/api` 路径。账号令牌只存于 `HttpOnly; SameSite=Lax; Path=/` Cookie，不放在 localStorage、URL 或 JSON 响应。生产通过 HTTPS 提供服务时设置 `AUTH_COOKIE_SECURE=1`；当前 HTTP/IP 访问可运行，但 HTTP 下会话 Cookie 以明文传输，可被中间人截获并冒用该昵称，公网部署应启用 HTTPS。请求体里已没有密码这类长期凭据，但昵称本身就是全部凭据，同样会在明文链路上暴露。

`accounts` 只存随机账号 ID、规范化昵称、`password_hash` 和创建时间：该列仅为兼容旧库结构保留，新账号写入空字符串，**旧库里残留的哈希不再校验**，老账号照常可进入；服务端没有任何需要保密的账号凭据。`account_sessions` 每个账号只留一条 SHA-256 令牌摘要与到期时间，令牌为 32 字节随机数，库中只存摘要，校验按摘要精确匹配。

服务器连接 IP 每 15 分钟最多 60 次 register 请求、60 次 login 请求（两个动作分开计算）；同一昵称每 15 分钟最多 30 次进入尝试，且成功后**不清除**计数——没有凭据可校验，限流是唯一能挡住遍历昵称与刷库的手段。同时进行的进入操作最多 2 个，超出返回 503 并带 `Retry-After`。计数保存在 SQLite，重启不能绕过。IP 使用 socket 地址，不信任客户端提供的 X-Forwarded-For；若后续加反向代理，应另行配置可信代理身份，否则共享代理出口也会共享限额。`login` 请求体上限 16 KiB，`register` 为进度快照 256 KiB 另加协议字段开销，过大、异常输入和服务忙碌都返回可见错误。

上榜仍由共享规则重放验证；身份改由会话提供，忽略伪造的客户端 playerId，收完回放后再检查会话，防止上传期间被踢下线仍成功上榜。公开榜可未登录查看，但个人名次只根据当前会话返回。成长快照只接受游戏存档键，不含会话令牌，也不含任何账号凭据；服务器提供保存与版本保护，快照本身仍由客户端产生，并非服务端金币账本。

## 查看与处置账号

账号只有昵称，没有密码，因此**不存在重置密码**：昵称被他人占用或冒用时，唯一处置手段是让对方的登录失效。服务器上在项目目录执行：

```bash
# 列出账号
node scripts/accounts.mjs list

# 让某个昵称现有的登录失效（不删进度）
node scripts/accounts.mjs sessions <昵称>
```

`sessions` 只删除该账号的会话记录，已登录的客户端需要重新输入昵称，进度仍留在库中；由于没有密码，对方重新输入同一昵称仍可再次进入，必要时需另行改名或删除该账号（暂无脚本，直接操作 SQLite）。数据库默认取项目内的 `server/data/game.db`，也可用 `DATA_DIR` 指定其他目录。

## 实现与验证

- `server/auth-store.mjs`：账号（昵称）创建与进入、会话、限流和账号成长事务。
- `server/auth.mjs`：Cookie、请求校验和认证 HTTP 接口。
- `src/features/auth/`：昵称输入界面、会话检查、请求和共享输入规则（`validation.mjs` 只导出 `ACCOUNT_HINT` 与 `normalizeAccount`）。
- `src/utils/accountStorage.ts`：游客与账号存档作用域、旧版迁移和云端版本。

测试覆盖昵称特殊字符与大小写、长度边界、令牌摘要、重复/并发进入、会话替换与过期、重启保留、旧会话退出不影响新登录、CSRF 写请求保护、请求限额、体积限制、伪造玩家 ID、存档隔离、失败写入、重复提交、断网重连与页面卸载。浏览器通过本机 `127.0.0.1` 实测进入与刷新。

Cookie 处理参考 [OWASP Session Management Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/Session_Management_Cheat_Sheet.html)。免密登录把身份验证降级为「知道昵称即可」，属于有意识的产品取舍，如需更强保护应另行引入邮箱/第三方登录，而不是恢复密码。
