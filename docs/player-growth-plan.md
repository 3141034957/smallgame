# 怪潮乐队：玩家成长路径与生存机制规划

日期：2026-10-06。基线：`59ba593`，`farm:v6-levels`。

**修订：永久强化树已实现并收紧回血与护盾，规则版本为 `farm:v8-recovery`。** 八项强化全部开放，仅受金币余额与各项等级上限限制，不与关卡、精英、Boss、进化或游玩时间绑定。购买与免费重置使用现有本地钱包，效果从下一局生效；回血与补盾已接入共享战斗与回放规则。下文经济采样仍来自改动前的基线，后期卡池、可信服务端账本和长局上传属于后续规划。参数还需真人平衡验证。

## 1. 推荐方向

增加自动回血和自动补盾，并把「升级」放在角色商店旁边。金币强化对所有角色通用，下局生效。整体形成三层成长：

| 成长层   | 玩家获得什么                                   | 边界                             |
| -------- | ---------------------------------------------- | -------------------------------- |
| 局内构筑 | 乐器、装备、终极进化、无限角色等级             | 本局结束重置；满血卡继续保留     |
| 局外强化 | 生命、攻击、移速、拾取、经验、减伤、回血、护盾 | 消耗现有金币，有明确等级上限     |
| 生涯目标 | 构筑提示、收藏目标、后期挑战目标               | 提供游玩方向，不限制永久强化购买 |

无限的是局内角色等级和挑战空间。基础强化收敛到有限上限，使新玩家能追上，也为后期构筑和操作保留价值。

回血奖励玩家摆脱围攻后的恢复；护盾偶尔救下一次失误。两者都不能靠暂停、打开商店或满血等待储存多次触发。

### 本次基线采样

使用 [check-farm-balance.mjs](../scripts/check-farm-balance.mjs)：六种每日词缀各取一个日期种子，每个种子遍历十个乐器意向配置，自动选择升级、躲避最近怪物、满能量释放。`startHolding=false`，没有注入经验、装备或无敌状态。

开场随机牌不一定包含意向乐器，脚本会转向已持有乐器，因此 **60 个配置样例不等于 60 个独立构筑或真实玩家样本**。下表金币是已拾取到模拟状态中的金币；运行到时间上限时未死亡的样例没有实际完成结算。

| 模拟时长上限 | 金币最小值 | 金币中位值 | 金币最大值 | 到达上限的配置数 |
| ------------ | ---------- | ---------- | ---------- | ---------------- |
| 30 秒        | 2,754      | 3,500      | 5,598      | 60/60            |
| 90 秒        | 17,754     | 20,254     | 28,155     | 60/60            |
| 180 秒       | 44,550     | 58,741     | 156,910    | 60/60            |
| 300 秒       | 52,750     | 110,712    | 384,420    | 40/60            |

300 秒样例的首个升级时间为 0.125–6.25 秒，中位值 6.125 秒；首次进化为 19.0625–26.125 秒，中位值 24.4375 秒。起始附近本来就有可击败的小怪，0.125 秒是特定种子的模拟结果。存活时间为 182.5625–300 秒，达到 300 秒的结果属于截尾数据，不能解释为最终死亡时间。

**设计影响：** 100 金币起步会使强化过快买满；成长速度使用价格曲线控制，不设战斗解锁门槛。另一方面，现有掉落、满血卡已经支持较长生存，增加生存能力必须做叠加验证。金币样例差距较大，也不能仅按中位值承诺玩家多久满级。

复现 300 秒总体结果：`node scripts/check-farm-balance.mjs`。复现经济表可在项目根目录执行：

```sh
node --input-type=module <<'JS'
import { modifierDays, simulateFarm } from './scripts/check-farm-balance.mjs'
import { RECIPES } from './src/features/farm/rules.mjs'
const range = values => {
  const sorted = values.sort((a, b) => a - b)
  return [sorted[0], sorted[Math.floor(sorted.length / 2)], sorted.at(-1)]
}
for (const limit of [30, 90, 180, 300]) {
  const runs = modifierDays().flatMap(day =>
    RECIPES.map(({ weapon }) => simulateFarm(day, weapon, true, limit)))
  console.log({ limit, coins: range(runs.map(run => run.coins)),
    reachedLimit: runs.filter(run => run.seconds === limit).length })
}
JS
```

## 4. 八项永久强化：首轮参数

强化全角色通用。外观名称、乐器卡与乐队成员继续使用统一身份配置。购买不改变正在进行的对局。

| 分类     | 名称     | 每级效果                               | 上限  | 满级效果            | 基础价格 B / 专用价格                      |
| -------- | -------- | -------------------------------------- | ----- | ------------------- | ------------------------------------------ |
| 生存保障 | 舞台体魄 | 最大生命 +5                            | 12 级 | 初始生命 160        | 1,500                                      |
| 攻击成长 | 乐感力量 | 全部玩家攻击伤害 +2%                   | 15 级 | +30%                | 2,000                                      |
| 操作手感 | 轻快步伐 | 移动速度 +1%                           | 10 级 | +10%                | 1,800                                      |
| 操作手感 | 音符吸引 | 基础拾取半径 +4%                       | 10 级 | +40%                | 1,500                                      |
| 攻击成长 | 演奏领悟 | 获得经验 +2%                           | 10 级 | +20%                | 2,500                                      |
| 生存保障 | 舞台护甲 | 受到的生命伤害降低 2 个百分点          | 6 级  | 减伤 12%            | 3,500                                      |
| 生存保障 | 生命回响 | 安全恢复，每次恢复 1/1.5/2/2.5/3 生命  | 5 级  | 每 12 秒恢复 3 生命 | 3,500 / 14,000 / 35,000 / 80,000 / 160,000 |
| 生存保障 | 守护音盾 | 空盾时自动补 1 层，间隔 180/150/120 秒 | 3 级  | 间隔 120 秒         | 18,000 / 70,000 / 200,000                  |

合计 71 个强化等级。这里收紧了此前讨论中生命与攻击的候选上限，以给新增回血、减伤和护盾留出空间。

不另外加入攻速、暴击、吸血、复活、无限叠加护甲。当前装备已经覆盖节奏、暴击等构筑能力，第一版先让这八项清楚可用。

### 属性计算口径

- 生命：开局按强化后的上限满血。商店购买、切角色、重置强化都不改变本局生命或上限。
- 攻击：每次实际伤害统一乘 `1 + 0.02 × 等级`，在乐器与装备效果之后应用一次；覆盖音浪、音刃、残留、采样、终极形态与爆发，不能在连锁中重复乘算。使用固定精度累积小数伤害，避免低伤害攻击因逐次取整而吃不到加成。
- 移速：玩家步长乘 `1 + 0.01 × 等级`，输入限制和服务端移动校验采用同一结果。视觉插值不会额外增加速度。
- 拾取：在现有拾音器等加成结果上乘 `1 + 0.04 × 等级`，不扩大攻击范围；Boss 和爆发的全场吸取维持其原规则。
- 经验：经验掉落在当前阶段、词缀、装备计算后乘 `1 + 0.02 × 等级`，用固定精度累计；只加经验，不加金币，已经生成的掉落不因购买重新计算。
- 护甲：没有盾时，实际生命伤害乘 `1 - 0.02 × 等级`。护盾优先吸收整次伤害，护甲不会让一层盾挡两次；各类怪物伤害一致处理。

属性加法在同项强化内累计，乘法只在明确的不同来源之间应用。前后端共用同一纯函数，不能让每种武器或界面分别解释参数。

## 5. 自动回血：给走位后的恢复机会

### 为什么选择安全恢复

| 候选机制             | 对现有游戏的影响                                             | 本轮决定                     |
| -------------------- | ------------------------------------------------------------ | ---------------------------- |
| 无条件每秒回血       | 能帮助新手，但容易与满血卡、爱心共同支撑站桩                 | 先采用受击打断的安全恢复     |
| 按最大生命百分比回血 | 生命强化同时提高血量和回复量，两个分支产生额外乘法增长       | 首版使用固定生命数值         |
| 击杀回血或攻击吸血   | 清怪更快的构筑恢复更多；多段、残留、连锁攻击还需统一触发次数 | 暂缓，留作以后互斥的构筑方向 |
| 走位后安全恢复       | 给受伤玩家明确的拉开间隙目标；不同武器攻击次数不影响恢复     | 作为第一版回血规则           |

**首选规则：最后一次有效受击后安全等待 8 秒，再累计 12 秒回血周期。第一口发生在受击后第 20 秒，以后每 12 秒一次。** 回复量固定为 1/1.5/2/2.5/3 生命，不按最大生命百分比恢复。

时间都使用战斗模拟帧，16 FPS 下安全期 128 帧、回复周期 192 帧。

| 事件                             | 回血处理                               |
| -------------------------------- | -------------------------------------- |
| 实际扣血，或护盾挡住一次有效攻击 | 重置安全期与回血周期                   |
| 一秒无敌期间忽略的碰撞           | 不额外重置；该碰撞不是有效受击         |
| 没有受击且仍缺血                 | 安全期结束后累计回血周期               |
| 满血，包括爱心或满血卡补到满血   | 清空回血周期；不储存多次回复           |
| 满血卡只改变生命                 | 不重置受击记录，不清除预警，不生成护盾 |
| 暂停、升级选择、商店、后台暂停   | 不推进恢复计时                         |
| 致命受击                         | 先死亡结算，回血不能将角色复活         |

例：00:20 被击中，00:28 安全期结束，00:40 恢复第一口。00:38 再次受击，则改为 00:58 恢复第一口。攻击怪物不打断回血，否则自动攻击游戏里几乎无法恢复。

一级理论持续回复速率约 0.083 生命/秒，满级 0.25 生命/秒（比上一版满级降低 75%），实际还受安全期和满血截断影响。满级减伤后普通一次 12 点接触伤害为 10.56，持续贴身受击会打断恢复。**这个算术说明回血本身不能抵消持续受击，不证明它与满血卡、爱心和护盾叠加后一定平衡。**

HUD 使用一个小生命音符提示「安全等待 8s / 下一口 12s」；不为每一次少量回血弹出遮挡战场的长文案。

## 6. 自动护盾：只在空盾时补一次

沿用现有「每层挡一次完整伤害」模型。自动产生与击杀掉落共享层数，上限仍为 3，自动补盾只在层数为 0 时工作。

暂不再增加一条「护盾生命值」。当前大怪和小怪单次伤害差异较大，整次挡伤的价值已经由玩家躲避与受击时机决定；沿用层数能让旧掉落和新恢复使用同一种直观规则。

1. 开局 0 层，不免费赠送开场盾；空盾计时从开局开始。
2. 最后一层盾被打破时，空盾计时归零；拾取盾或自动获得盾后也归零。
3. 只在空盾时连续累计 180/150/120 秒模拟时间；有盾时不能储存下一层的进度。
4. 连续空盾且未受击的计时达到要求，自动获得 1 层，不一次生成多层。
5. 普通生命受击同样将全部补盾计时清零；一秒无敌期间被忽略的攻击不计入有效受击。
6. 同帧拾取掉落盾和补盾就绪时，优先处理拾取，自动补盾取消。这一帧不能凭空得到 2 层。

例：三级音盾在 01:20 破掉最后一层，最早 03:20 补 1 层；若 03:18 受击，则最早 05:18 补。若 02:00 拾取到掉落盾，03:20 不再补盾；这层拾取盾以后破掉时重新开始 120 秒计时。

自动盾同样触发现有挡伤保护，同时重置回血的安全期。这样两条防御不会在被包围时自动轮流续命。显示「补盾 120s」，有盾时显示层数。击杀掉落盾的最短间隔也从 20 秒提高到 45 秒，避免叠加频繁续盾。

## 7. 全部开放的永久强化树

进入游戏即可查看和购买全部八项强化。三条分支只做分类展示，每个节点独立升级，没有前置节点、关卡或成就要求。有足够金币时，任意一项都可以直接连续买到自身上限。

| 分支     | 节点                           | 购买条件             |
| -------- | ------------------------------ | -------------------- |
| 生存保障 | 生命、护甲、自动回血、自动护盾 | 金币足够且该项未满级 |
| 攻击成长 | 攻击、经验                     | 金币足够且该项未满级 |
| 操作手感 | 移速、拾取                     | 金币足够且该项未满级 |

玩家成长依靠「完成演出 → 获得金币 → 自由分配强化 → 下一局体验变化」循环。首轮先完成这棵树，收藏、进化与技巧成就只提供额外目标，不限制树的购买进度。

### 三条入门路线

| 路线     | 推荐购买顺序                                        | 想解决的问题                               |
| -------- | --------------------------------------------------- | ------------------------------------------ |
| 容错练习 | 生命 1 → 回血 1 → 拾取 1 → 生命 3 → 护甲 1 → 护盾 1 | 一次走位失误后有恢复机会，少为拾取钻入怪群 |
| 快速成团 | 攻击 1 → 拾取 1 → 经验 1 → 攻击 3 → 移速 1          | 更快完成主乐器与配对装备，体验进化         |
| 走位挑战 | 移速 1 → 攻击 1 → 拾取 1 → 移速 3 → 护盾 1          | 依靠操作避开冲刺和砸地，用盾兜住偶发失误   |

路线是推荐，不是三个互斥职业。玩家随时能局间免费重置，用已花金币重新分配。第一版只用这一层选择，熟悉后再评估是否需要互斥天赋。

| 护盾 | 18,000     | 288,000       |
| 全部 | —          | **1,824,600** |

生命 1 + 拾取 1 + 回血 1 的组合需 6,500；生命前三级合计 8,000。这种前期定价能让当前 30 秒自动样例的收入买到一两项实用强化，而高级强化仍需要多局选择。若未来改变金币产出，必须同步重算价格。

满级总成本约等于当前 300 秒金币中位值的 16.5 倍；这个比值只是购买规模对比，**不是 16.5 局满级承诺**。样例多数未结算，强化会反过来提高生存与收入，还存在种子、构筑、操作者和迁移存档差异。

先不新增金币倍率强化。经验强化促进进化已经能间接增加收入，再加金币倍率容易使最优购买路线变成单一的经济滚雪球。

退款在局间完成，返还该玩家账本中真实支付的金币；调价之后也不能按新价退款套利。退款不撤销已达成里程碑，但清空相应购买等级。进行中对局使用开局快照，退款不能即时治疗或改变本局。

现有角色价格先保留。模拟显示外观总价相对于熟练样例的一局收入较低，后续可增加演出/收藏解锁条件来延长收集乐趣；改动旧角色价格和旧余额另作明确迁移决定。

## 9. 局内节奏、满级后成长与敌人压力

永久经验、攻击强化都可能令进化更早。先保留现在的卡池与进化配对规则，用新手和满强化数据比较，不同时改变所有系统。

| 本局时间   | 已有敌人节奏                         | 新成长系统的目标                                       |
| ---------- | ------------------------------------ | ------------------------------------------------------ |
| 0–30 秒    | 追击音团、蝙蝠、噪音怪逐渐出现       | 快速建立主乐器；看到成长，不靠开场盾无脑站住           |
| 35–60 秒   | 重装怪、精英、第一 Boss              | 学会识别预警、躲避冲刺；掉落奖励击杀，回血奖励拉开间隙 |
| 60–120 秒  | 两类 Boss、精英弹幕开始形成压力      | 利用走位与稀有掉落盾救场，自动盾必须长时间脱离围攻     |
| 120–180 秒 | 扇形射击、追加砸地、怪物生命继续增长 | 构筑和操作共同决定生存，第二套进化成为目标             |
| 180 秒以后 | 持续怪潮与 Boss 补充                 | 多套进化、爆发时机、恢复选择支撑长局，仍保留失败风险   |

短弓词缀已有 Boss 提前规则，阶段提示必须从同一怪物配置读取，不把 60/90 秒写死在 UI。

**后续局内扩展，独立于第一版永久强化：** 当前装备满级后只剩满血卡，长期升级选择会趋于重复。建议扩展为：满血恢复、临时获得 1 层盾（未满 3 层时可出现）、本局最终伤害 +1%（最多选择 20 次）。在普通装备阶段保持现有满血卡参与概率；新的尾声卡只在没有可强化装备时加入。

新尾声池最多提供三张不同卡。伤害强化到上限、盾也满时，至少保留满血卡作为合法选择；即使满血也允许选择，经验与等级不会卡死。卡池是否需要更丰富的后期方向留到真人测试，不用无限伤害、无限复活或额外金币奖励维持等级。

永久攻击与尾声攻击分属两个乘区，满级合计 `1.30 × 1.20 = 1.56`，须在叠加测试中覆盖；本局生命恢复卡不改变这两个数值。增加这些规则时升级规则版本，隔离旧回放。

## 10. 页面与操作

首页「角色商店」旁放「升级」，结算页也放入口。标题「乐队升级」，副标题「强化所有角色，下局生效」。

- 顶部：金币余额、已购强化等级 `12/71`、免费重置。
- 内容：生存保障 / 攻击成长 / 操作手感三组。每项展示名称、等级、当前效果、下级效果、价格与满级状态。
- 全部开放：不显示战斗解锁条件；金币不足时显示差额，满级时停止扣费。
- 购买：确认实际扣费结果后更新等级；余额不足、已满级、请求处理中均有清晰状态。快速连点不能重复扣款。
- 结算推荐：最多推荐一项，按失败原因或进度建议生命、移速、拾取等；不过度推荐防御，让攻击路线也有价值。
- 战斗中打开：暂停浏览；购买标明「下局生效」。关掉商店不会刷新生命、护盾或恢复计时。
- 角色卡：保留乐队集结的九位角色身份，不让外观价格暗示攻击或生命差异。

小屏幕用单列卡片，购买按钮与数值保持同一项内；横屏可两列。生命、护盾动画与敌人预警使用不同颜色和形状，避免盖住砸地范围。

## 11. 实现依赖与存档处理

### 共享规则与可信成长

当前钱包和任务主要存在本地，服务端只验证战斗过程，匿名 `playerId` 不是可靠的账户凭证。永久属性会直接改变移动、伤害和成绩，不能把客户端传来的强化等级当成真实购买结果。

后续要提供可信竞技与跨设备成长时，需要：服务端持有金币余额、强化等级、交易与结算去重记录；匿名玩家使用服务端签发的凭证绑定档案。购买使用事务完成「校验条件 → 扣币 → 升级」，幂等请求防重试和多标签页重复扣费。

开局创建对局记录，固定规则版本、日期种子、档案版本和强化快照。回放加载该快照，不读取结束时的当前档案。金币由共享规则计算并一次性入账；每日目标与里程碑奖励也由可信记录结算，不能继续让本地无限增币后用于竞技强化。

对修改本地档案、请求伪造等级、其他玩家档案、重复结算、重复退款、同时购买进行拒绝或冲突处理。强化版本更新后旧成绩保留，首版新规则榜单与旧版隔离；当前未展示当局强化总等级，也不保证不同强化玩家具有相同起点。

### 旧存档：不能静默清空

第一步读取并备份旧本地钱包、角色、任务、成就与生涯版本。有效已购外观、所选角色和收藏记录应尽量保留，未知身份继续走现有规范化处理。

**需要产品决定的迁移点：** 旧金币没有服务端来源账本，无法同时保证全部原额直接用于强化以及新榜单的可信公平。推荐方案是保留旧余额及其消费体验，标记迁移来源；使用迁移资金的强化记录进入同版本成长榜并显示迁移标记，避免把该榜宣传为严格公平竞技。若后续需要公平排名，再为同一冒险提供固定强化预算的比较规则。

旧余额首次迁移必须幂等、绑定新档案，不能靠换标签页重复导入。保留本地原档备份和明确恢复路径；迁移时展示保留的余额与外观，不自动删币，也不根据不可信余额授予竞技证明。浏览器匿名身份无法完全阻止新建档案或篡改首次导入，真实账户和迁移策略需要另行落实。

### 长局上传先补齐

游戏没有结束时间，但当前服务端拒绝超过十分钟的回放，且有 1 MiB 请求体上限。生存强化可能让更多人碰到这个边界，必须列为正式发布前依赖。

建议分批压缩上传输入，在服务端保留已验证模拟状态、帧序号与对局标识，后续分片只能接续；重复、缺片、乱序都要处理。长回放验证移到有时间和资源预算的工作线程，避免阻塞其他 API。仍保留单片大小、验证并发、空闲回收等限制，不能单纯删除原保护上限。

离线或上传失败保留本机对局，明确展示「待验证收益」，联网补交后一次入账；正式金币不能在失败重试中重复奖励。首版保留原有十分钟及请求体限制，超限继续显示上传失败并保留本机战绩；不声称长局上传已经完成。

| A：成长底座 | 统一强化配置、价格函数、档案版本、可信钱包/购买/退款/结算、开局快照、旧存档迁移说明 | 重复操作不多扣少扣；余额、条件、版本可校验；旧档可恢复     |
| B：基础强化 | 升级入口与页面；生命、攻击、移速、拾取、经验、护甲；八项全部开放                    | 前后端一致；全部乐器吃到应有加成；角色切换没有属性例外     |
| C：生存强化 | 回血、安全等待、自动补盾、计时提示；与现有治疗和护盾协调                            | 下述时序与叠加检查通过；自动补盾不能攒到三层               |
| D：发布准备 | 长局分片与异步验证、强化榜单版本、手机试玩与调参                                    | 超十分钟真实死亡记录可验证；错误可恢复；资源受限；真人通过 |
| E：长期内容 | 满装备尾声卡、进化收藏提示、技巧目标，视数据扩展                                    | 长期有选择；不重新扩张为多款游戏；不靠无限基础数值维持成长 |

本次先交付本地永久强化树及效果，榜单按客户端携带的有界开局强化快照重放，验证战斗结果，不验证购买来源。可信金币与服务端账本属于后续工作。第一版不把互斥天赋树、额外货币或新地图作为前置需求。

### 规则验收

- 回血：受击后第 20 秒首次恢复；间隔 12 秒；护盾受击重置；无敌忽略碰撞不重置；满血清空周期；暂停不推进；死者不恢复；最大生命不能被突破。
- 护盾：三个等级时间准确；只在空盾积累；任意有效受击清空全部补盾进度；拾取后计时清空；盾碎后从零开始；同帧拾取只得到掉落层；总层数 ≤3。
- 叠加：爱心、满血卡、爆发保护、受击无敌、护甲、自动回复和盾在同帧按约定顺序计算，死亡不被随后自动恢复撤销。保留现有拾取时序，在受击判定后再处理周期回血和自动补盾。
- 属性：十种乐器、各终极形态、残留与爆发的伤害倍率一致；移动校验随快照变化；拾取不改变攻击半径；经验不增加金币；不同外观同档案效果相同。
- 交易：余额不足、上限、陈旧等级、双击、跨标签页、并发、旧版本、失败重试、按原支出退款和迁移去重均有验证。
- 长局：10/20/30 分钟对局、断线补传、乱序/重复片段、非法续接、提前结束、死亡后输入与并发验证预算；局内仍允许等级无限提升。

### 平衡与真人验证

固定种子自动对比：无强化、新手组合、中期组合、满强化，覆盖六种词缀、十种乐器意向和站桩/简单绕圈/最近怪物躲避三类输入。分别记录真实死亡和达到 300/600 秒上限的截尾结果；不能将后者统计为死亡时间。

新增统计：金币、首次购买、首次进化、生命伤害、有效受击、回血量、各来源盾数量/挡伤次数、满血卡选择频率、等待恢复的时间。现有 300 秒绕圈样例是上一版强化树采样。本次新增无强化/低强化/满强化 × 六种词缀 × 站桩/绕圈/躲避共 54 局、600 秒上限，以及满强化站桩 6 局、1800 秒上限。详见 [恢复平衡验证](recovery-balance.md)。这不是全部构筑或真人平衡证明；更高移速也会改变拾取和接敌轨迹，收入并不保证逐样例单调上升。

首轮目标：新手每一到三局能做一次有感知的购买；低强化玩家仍能碰到精英和第一 Boss；满强化站桩不能在全部词缀下无限存活；防御与攻击路线都有实际优势。若站桩能由掉落和满血卡持续维持，优先调整自动恢复/补盾参数和其协同，再评估现有治疗，不直接删除用户要求的满血卡。

至少邀请新手与熟练玩家各 5 人，在手机触控与电脑各完成多局。检查首次失败是否知道下一步、自动回复是否可理解、盾是否清楚挡住一次攻击、基础强化是否让走位仍然重要。前 15/30/60 分钟的购买数量、死亡时间分布和选择偏好，再决定价格与回复参数。

当前确定推荐：八项强化、八秒安全期加十二秒回血周期、空盾 180→150→120 秒补一层且受击重计、全树开放与免费局间重置。需要实施阶段验证的事项：实际升级速度、防御叠加后的长局难度、旧金币迁移策略，以及可信成长和长局上传底座。
