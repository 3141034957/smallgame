# 怪潮乐队：玩家成长路径与生存机制规划

日期：2026-10-06。基线：`59ba593`，`farm:v6-levels`。

**修订：永久强化已从「八项 × 多级 + 百分比」重做为一条全局链，规则版本为 `farm:v10-flat-chain`。** 全链共 29 个单级节点（`step-1`…`step-29`），每个只能买一次，买下第 N 个才解锁第 N+1 个；加成全部是固定数值，链上不再出现任何百分比。节点只受金币余额与链上顺序限制，不与关卡、精英、Boss、进化或游玩时间绑定。购买与免费重置使用现有本地钱包，效果从下一局生效；回血与补盾已接入共享战斗与回放规则。Boss 仍为每两分钟交替登场。规则版本由 `farm:v9-boss-interval` 升到 `farm:v10-flat-chain`，旧 v9 成绩在数据库里保留但不再计入当前榜。下文经济采样仍来自改动前的基线，后期卡池、可信服务端账本和长局上传属于后续规划。参数还需真人平衡验证。

## 1. 推荐方向

增加自动回血和自动补盾，并把「升级」放在角色商店旁边。金币强化对所有角色通用，下局生效。整体形成三层成长：

| 成长层   | 玩家获得什么                                     | 边界                             |
| -------- | ------------------------------------------------ | -------------------------------- |
| 局内构筑 | 乐器、芯片、流派进化、跨流派组合技、无限角色等级 | 本局结束重置；满血卡继续保留     |
| 局外强化 | 生命、伤害、拾取、移速、经验、减伤、回血、补盾   | 消耗现有金币；29 个节点各买一次，按顺序解锁 |
| 生涯目标 | 构筑提示、收藏目标、后期挑战目标                 | 提供游玩方向，不限制永久强化购买           |

无限的是局内角色等级和挑战空间。局外强化收敛为一条有限长链，使新玩家能追上，也为后期构筑和操作保留价值。全链买满共 29 步，没有无限叠加的数值。

回血奖励玩家摆脱围攻后的恢复；护盾偶尔救下一次失误。两者都不能靠暂停、打开商店或满血等待储存多次触发。

### 本次基线采样

使用 [check-farm-balance.mjs](../scripts/check-farm-balance.mjs)：六种每日词缀各取一个日期种子，每个种子遍历十个乐器意向配置，自动选择升级、躲避最近怪物、满能量释放。`startHolding=false`，没有注入经验、装备或无敌状态。

开场随机牌不一定包含意向乐器，脚本会转向已持有乐器，因此 **60 个配置样例不等于 60 个独立构筑或真实玩家样本**。下表金币是已拾取到模拟状态中的金币；运行到时间上限时未死亡的样例没有实际完成结算。

| 模拟时长上限 | 金币最小值 | 金币中位值 | 金币最大值 | 到达上限的配置数 |
| ------------ | ---------- | ---------- | ---------- | ---------------- |
| 30 秒        | 2,754      | 3,500      | 5,598      | 60/60            |
| 90 秒        | 17,754     | 20,254     | 28,155     | 60/60            |
| 180 秒       | 44,550     | 58,741     | 156,910    | 60/60            |
| 300 秒       | 52,750     | 110,712    | 384,420    | 40/60            |

300 秒样例的首个升级时间为 0.125–6.25 秒，中位值 6.125 秒；首次进化为 19.0625–26.125 秒，中位值 24.4375 秒。起始附近本来就有可击败的小怪，0.125 秒是特定种子的模拟结果。存活时间为 182.5625–300 秒，达到 300 秒的结果属于截尾数据，不能解释为最终死亡时间。

**设计影响：** 100 金币起步会使强化过快买满；成长速度使用价格曲线控制，不设战斗解锁门槛。另一方面，现有掉落、满血卡已经支持较长生存，增加生存能力必须做叠加验证。金币样例差距较大，也不能仅按中位值承诺玩家多久满级。

复现 300 秒总体结果：`node scripts/check-farm-balance.mjs`。复现经济表可在项目根目录执行：

```sh
node --input-type=module <<'JS'
import { modifierDays, simulateFarm } from './scripts/check-farm-balance.mjs'
import { RECIPES } from './src/features/farm/rules.mjs'
const range = values => {
  const sorted = values.sort((a, b) => a - b)
  return [sorted[0], sorted[Math.floor(sorted.length / 2)], sorted.at(-1)]
}
for (const limit of [30, 90, 180, 300]) {
  const runs = modifierDays().flatMap(day =>
    RECIPES.map(({ weapon }) => simulateFarm(day, weapon, true, limit)))
  console.log({ limit, coins: range(runs.map(run => run.coins)),
    reachedLimit: runs.filter(run => run.seconds === limit).length })
}
JS
```

## 4. 永久强化链：29 个单级节点

强化全角色通用。外观名称、乐器卡与乐队成员继续使用统一身份配置。购买不改变正在进行的对局。

旧方案是八项各自多级、每级给百分比；现在是一条**全局链**：29 个节点顺序排列，每个节点 `max: 1`，只能买一次，买下第 N 个才解锁第 N+1 个。加成全部是固定数值，链上没有任何乘算百分比。

全链买满后的固定加成：`生命 160`（基础 100 + 6 × 10）、`伤害 +5`、`拾取 +32`、`移速 +6`（每秒距离单位）、`经验 +6`（每次经验掉落）、`减伤 3`、`回血 +2`（每 12 秒恢复量）、`补盾 120 秒`。

各效果的节点数量：生命 ×6、伤害 ×5、拾取 ×4、移速 ×3、经验 ×3、减伤 ×3、回血 ×2、补盾 ×3。补盾三个节点不是叠加：生效的是已购最后一个（180 → 150 → 120 秒）。

三条分支（生存保障 / 攻击成长 / 操作手感）现在只用于节点配色和分类标签，不再分组排版，也不再作为可跳过的路线。

不另外加入攻速、暴击、吸血、复活、无限叠加护甲。当前装备已经覆盖节奏、暴击等构筑能力，第一版先让这条链清楚可用。

### 属性计算口径

永久加成全部是固定数值，加在局内计算之后或之上；局内的百分比（力量、韧性、轻步等）仍按各自的乘区保留。

- 生命：开局按强化后的上限满血。商店购买、切角色、重置强化都不改变本局生命或上限。
- 伤害：`命中 = 基础伤害 × 暴击 × 局内倍率 + 永久伤害`。永久伤害在乐器、芯片、进化与局内倍率全部算完后加一次；覆盖音浪、音刃、残留、采样、终极形态与爆发，不能在连锁中重复加算。使用固定精度累积小数伤害，避免低伤害攻击因逐次取整而吃不到加成。
- 受击：没有盾时，`实际伤害 = max(0, 伤害 × 局内韧性 − 永久减伤)`。护盾优先吸收整次伤害，减伤不会让一层盾挡两次；各类怪物伤害一致处理。
- 移速：`步长 = MOVE_STEP × (1 + 局内轻步 × 0.01) + 永久移速 / FPS`。永久部分是每秒距离单位，按帧摊到每一步；输入限制和服务端移动校验采用同一结果。视觉插值不会额外增加速度。
- 拾取：`半径 = (15 + 拾音器 × 15 + 永久拾取) × 跨流派组合技的拾取倍率`。不扩大攻击范围；Boss 和爆发的全场吸取维持其原规则。
- 经验：`掉落 = round(阶段基础值 × 阶段倍率 × 词缀倍率) + 永久经验`。只加经验，不加金币；已经生成的掉落不因购买重新计算。
- 回血：安全期结束后每 12 秒恢复 `永久回血` 点（两个节点各 +1，最多 2 点），不按最大生命百分比恢复。
- 补盾：空盾累计到已购最后一个节点的秒数（180 / 150 / 120）时补 1 层，计时规则见第 6 节。

永久项一经购买，当帧起在共享纯函数里生效，前后端同值。不能让每种武器或界面分别解释参数。

## 5. 自动回血：给走位后的恢复机会

### 为什么选择安全恢复

| 候选机制             | 对现有游戏的影响                                             | 本轮决定                     |
| -------------------- | ------------------------------------------------------------ | ---------------------------- |
| 无条件每秒回血       | 能帮助新手，但容易与满血卡、爱心共同支撑站桩                 | 先采用受击打断的安全恢复     |
| 按最大生命百分比回血 | 生命强化同时提高血量和回复量，两个分支产生额外乘法增长       | 首版使用固定生命数值         |
| 击杀回血或攻击吸血   | 清怪更快的构筑恢复更多；多段、残留、连锁攻击还需统一触发次数 | 暂缓，留作以后互斥的构筑方向 |
| 走位后安全恢复       | 给受伤玩家明确的拉开间隙目标；不同武器攻击次数不影响恢复     | 作为第一版回血规则           |

**首选规则：最后一次有效受击后安全等待 8 秒，再累计 12 秒回血周期。第一口发生在受击后第 20 秒，以后每 12 秒一次。** 回复量是链上两个「回血 +1」节点之和，买一个每口恢复 1 点、买两个每口恢复 2 点，不按最大生命百分比恢复，也没有小数量级。

时间都使用战斗模拟帧，16 FPS 下安全期 128 帧、回复周期 192 帧。

| 事件                             | 回血处理                               |
| -------------------------------- | -------------------------------------- |
| 实际扣血，或护盾挡住一次有效攻击 | 重置安全期与回血周期                   |
| 一秒无敌期间忽略的碰撞           | 不额外重置；该碰撞不是有效受击         |
| 没有受击且仍缺血                 | 安全期结束后累计回血周期               |
| 满血，包括爱心或满血卡补到满血   | 清空回血周期；不储存多次回复           |
| 满血卡只改变生命                 | 不重置受击记录，不清除预警，不生成护盾 |
| 暂停、升级选择、商店、后台暂停   | 不推进恢复计时                         |
| 致命受击                         | 先死亡结算，回血不能将角色复活         |

例：00:20 被击中，00:28 安全期结束，00:40 恢复第一口。00:38 再次受击，则改为 00:58 恢复第一口。攻击怪物不打断回血，否则自动攻击游戏里几乎无法恢复。

买一个回血节点的理论持续回复速率约 0.083 生命/秒，两个节点 0.167 生命/秒（低于更早版本满级的 1 生命/秒），实际还受安全期和满血截断影响。减伤买满（3 点）后普通一次 12 点接触伤害为 9，持续贴身受击会打断恢复。**这个算术说明回血本身不能抵消持续受击，不证明它与满血卡、爱心和护盾叠加后一定平衡。**

HUD 使用一个小生命音符提示「安全等待 8s / 下一口 12s」；不为每一次少量回血弹出遮挡战场的长文案。

## 6. 自动护盾：只在空盾时补一次

沿用现有「每层挡一次完整伤害」模型。自动产生与击杀掉落共享层数，上限仍为 3，自动补盾只在层数为 0 时工作。

补盾间隔由链上第 16、24、29 三个节点给出（180 / 150 / 120 秒），生效的是已购最后一个：只买到第 16 步就是 180 秒，三个都买到才是 120 秒。

暂不再增加一条「护盾生命值」。当前大怪和小怪单次伤害差异较大，整次挡伤的价值已经由玩家躲避与受击时机决定；沿用层数能让旧掉落和新恢复使用同一种直观规则。

1. 开局 0 层，不免费赠送开场盾；空盾计时从开局开始。
2. 最后一层盾被打破时，空盾计时归零；拾取盾或自动获得盾后也归零。
3. 只在空盾时连续累计 180/150/120 秒模拟时间；有盾时不能储存下一层的进度。
4. 连续空盾且未受击的计时达到要求，自动获得 1 层，不一次生成多层。
5. 普通生命受击同样将全部补盾计时清零；一秒无敌期间被忽略的攻击不计入有效受击。
6. 同帧拾取掉落盾和补盾就绪时，优先处理拾取，自动补盾取消。这一帧不能凭空得到 2 层。

例：三级音盾在 01:20 破掉最后一层，最早 03:20 补 1 层；若 03:18 受击，则最早 05:18 补。若 02:00 拾取到掉落盾，03:20 不再补盾；这层拾取盾以后破掉时重新开始 120 秒计时。

自动盾同样触发现有挡伤保护，同时重置回血的安全期。这样两条防御不会在被包围时自动轮流续命。显示「补盾 120s」，有盾时显示层数。击杀掉落盾的最短间隔也从 20 秒提高到 45 秒，避免叠加频繁续盾。

## 7. 一条按顺序解锁的全局链

进入游戏即可查看整条链。29 个节点全部公开显示，但只有链上的下一个可买：买下第 N 个才解锁第 N+1 个，不能跳步。因此没有分支前置、关卡或成就要求，也不需要选择路线——所有玩家的解锁顺序相同，差别只在于买到了第几步。

| 状态     | 界面呈现                          | 可购买条件                     |
| -------- | --------------------------------- | ------------------------------ |
| 已获得   | 实心节点 + 图标 +「已获得 ✓」     | 已买下，不可重复购买           |
| 下一个   | 高亮节点 + 价格按钮（金币不足显示差额） | 是链上第一个未拥有的节点，且金币足够 |
| 未解锁   | 🔒 +「未解锁 · 分支名」           | 前面的节点还没买完，不能购买   |

跳步购买会被直接拒绝并提示「前面的强化还没升级。」；价格沿链递增，越靠后的节点越贵。

玩家成长依靠「完成演出 → 获得金币 → 沿链推进 → 下一局体验变化」循环。首轮先完成这条链，收藏、进化与技巧成就只提供额外目标，不限制链的推进。

链的顺序本身承担了旧版「三条入门路线」的引导作用：前几步依次给出生命、伤害、拾取、移速，玩家不需要事先理解分支就能获得可感知的提升；生存、攻击与操作类节点在链上交错出现，不需要玩家自己分配。分支标签（生存保障 / 攻击成长 / 操作手感）只用于节点配色和分类说明。

玩家随时能局间免费重置，用已花金币沿链重新购买。第一版只用这一层选择，熟悉后再评估是否需要互斥天赋。

## 8. 金币经济与退款

继续使用现有金币。角色商店与强化共用余额，界面明确说明角色只改变外观；新手不必先买角色才能变强。

整条链共用一个价格公式，价格只由节点在链上的序号决定（序号 `i` 从 0 开始）：

```
价格 = 50 × round(1200 × (1 + 0.25i + 0.06i²) / 50)
```

第 1 步为 1,200，第 29 步为 66,050，中间每步递增。不再区分「基础价格」和「专用价格」，回血与补盾也按同一条曲线定价。

| 位置       | 第 1 步 | 前 5 步 | 前 10 步 | 前 15 步 | 前 20 步 | 前 25 步 | 全部 29 步  |
| ---------- | ------- | ------- | -------- | -------- | -------- | -------- | ----------- |
| 单步价格   | 1,200   | 3,550   | 9,750    | 19,500   | 32,900   | 49,850   | 66,050      |
| 累计总花费 | 1,200   | 11,150  | 46,050   | 122,550  | 258,850  | 472,800  | **712,000** |

前 3 步（生命 +10、伤害 +1、拾取 +8）合计 4,850；前 5 步合计 11,150。这种前期定价能让当前 30 秒自动样例的收入买到前几步实用强化，而链尾仍需要多局积累。若未来改变金币产出或链长，必须同步重算价格。

全部买满 712,000 金币，约等于当前 300 秒金币中位值（110,712）的 6.4 倍；这个比值只是购买规模对比，**不是 6.4 局买满承诺**。样例多数未结算，强化会反过来提高生存与收入，还存在种子、构筑、操作者和存档差异。

先不新增金币倍率节点。链上的经验节点促进进化已经能间接增加收入，再加金币倍率容易使推进顺序变成单一的经济滚雪球。

退款在局间完成，返还该玩家账本中真实支付的金币；调价之后也不能按新价退款套利。退款不撤销已达成里程碑，但把链清空回第 1 步之前（免费重置为全额返还）。进行中对局使用开局快照，退款不能即时治疗或改变本局。

现有角色价格先保留。模拟显示外观总价相对于熟练样例的一局收入较低，后续可增加演出/收藏解锁条件来延长收集乐趣；改动旧角色价格和旧余额另作明确迁移决定。

## 9. 局内节奏、满级后成长与敌人压力

链上的永久经验与伤害都可能令进化更早。先保留现在的卡池与进化配对规则，用新手和买满链的数据比较，不同时改变所有系统。

| 本局时间   | 已有敌人节奏                           | 新成长系统的目标                                       |
| ---------- | -------------------------------------- | ------------------------------------------------------ |
| 0–30 秒    | 追击音团、蝙蝠、噪音怪逐渐出现         | 快速建立主乐器；看到成长，不靠开场盾无脑站住           |
| 35–60 秒   | 重装怪、精英                           | 学会识别预警、躲避冲刺；掉落奖励击杀，回血奖励拉开间隙 |
| 60–120 秒  | 精英弹幕形成压力，120 秒首个 Boss 登场 | 利用走位与稀有掉落盾救场，自动盾必须长时间脱离围攻     |
| 120–180 秒 | 扇形射击、追加砸地、怪物生命继续增长   | 构筑和操作共同决定生存，第二套进化成为目标             |
| 180 秒以后 | 持续怪潮，每两分钟交替补充 Boss        | 多套进化、爆发时机、恢复选择支撑长局，仍保留失败风险   |

Boss 在 120/240 秒首次交替登场，之后每 120 秒出现一只，不受短弓词缀影响。阶段提示从同一怪物配置读取，不在 UI 写死时间。

**后续局内扩展，独立于第一版永久强化：** 当前装备满级后只剩满血卡，长期升级选择会趋于重复。建议扩展为：满血恢复、临时获得 1 层盾（未满 3 层时可出现）、本局最终伤害 +1%（最多选择 20 次）。在普通装备阶段保持现有满血卡参与概率；新的尾声卡只在没有可强化装备时加入。

新尾声池最多提供三张不同卡。伤害强化到上限、盾也满时，至少保留满血卡作为合法选择；即使满血也允许选择，经验与等级不会卡死。卡池是否需要更丰富的后期方向留到真人测试，不用无限伤害、无限复活或额外金币奖励维持等级。

永久伤害与局内攻击加成不属于同一位置：局内加成是乘区（如「力量」每级 +3%，满 5 级为 ×1.15），永久伤害是乘完后加上的固定值（满链 +5），不能简单写成两个倍率相乘。两者叠加须在测试中覆盖；本局生命恢复卡不改变这两个数值。增加这些规则时升级规则版本，隔离旧回放。

## 10. 页面与操作

首页「角色商店」旁放「升级」，结算页也放入口。标题「乐队升级」，副标题「强化所有角色，下局生效」。

- 顶部：金币余额、已购节点数 `N/29`、免费重置。
- 内容：一条竖链，29 个节点按顺序列出，左侧连线显示推进进度。节点三种状态——已获得（实心 + 图标 +「已获得 ✓」）、下一个可买（高亮 + 价格按钮）、未解锁（🔒 +「未解锁 · 分支名」）。
- 分支标签（生存保障 / 攻击成长 / 操作手感）只决定节点配色和未解锁时的分类说明，不再分组排版。
- 全部可见：不显示战斗解锁条件；金币不足时在按钮下显示差额；跳步购买提示「前面的强化还没升级。」。
- 购买：确认实际扣费结果后更新链上进度；余额不足、未解锁、请求处理中均有清晰状态。快速连点不能重复扣款。
- 结算推荐：最多推荐一项，按失败原因或进度建议链上的下一步；不过度推荐防御，让伤害路线也有价值。
- 战斗中打开：暂停浏览；购买标明「下局生效」。关掉商店不会刷新生命、护盾或恢复计时。
- 角色卡：保留乐队集结的九位角色身份，不让外观价格暗示攻击或生命差异。

小屏幕用单列竖链，购买按钮与数值保持在同一节点内；横屏可两列。生命、护盾动画与敌人预警使用不同颜色和形状，避免盖住砸地范围。整页允许滚动，进入战斗的选择页与结算页仍要求一屏放下。

## 11. 实现依赖与存档处理

### 共享规则与可信成长

当前钱包和任务主要存在本地，服务端只验证战斗过程，匿名 `playerId` 不是可靠的账户凭证。永久属性会直接改变移动、伤害和成绩，不能把客户端传来的强化等级当成真实购买结果。

后续要提供可信竞技与跨设备成长时，需要：服务端持有金币余额、强化等级、交易与结算去重记录；匿名玩家使用服务端签发的凭证绑定档案。购买使用事务完成「校验条件 → 扣币 → 升级」，幂等请求防重试和多标签页重复扣费。

开局创建对局记录，固定规则版本、日期种子、档案版本和强化快照。回放加载该快照，不读取结束时的当前档案。金币由共享规则计算并一次性入账；每日目标与里程碑奖励也由可信记录结算，不能继续让本地无限增币后用于竞技强化。

对修改本地档案、请求伪造等级、其他玩家档案、重复结算、重复退款、同时购买进行拒绝或冲突处理。强化版本更新后旧成绩保留：规则版本升到 `v10-flat-chain` 后，v9 及更早的成绩继续留在数据库，但当前榜只读新版本前缀，旧版本提交返回 409 并提示刷新；本机最佳纪录键同样按版本隔离。当前未展示当局强化进度，也不保证不同强化玩家具有相同起点。

### 旧存档：强化数据直接清空，其余进度保留

第一步照旧读取并备份旧本地钱包、角色、任务、成就与生涯版本。金币余额、已解锁角色、当前选择、有效已购外观和收藏记录继续保留，未知身份继续走现有规范化处理。

**旧的多级强化存档不折算，直接清空。** 旧档的 `vitality`、`power`、`armor`、`regen`、`shield`、`wisdom`、`stride`、`magnet` 这八个键在新链里不存在，`normalizePermanentLevels` 把它们读成 29 项全 0，也就是一条尚未开始的链。

清空而不是折算，是因为两者没有对应关系：旧树是可买到多级、以百分比生效的八项，新链是 29 个只买一次、全部为固定数值的节点。任何折算比例都只是工程上的近似，会凭空给出玩家并没有按当前价格购买的节点，也会让「已购节点数」与真实支出对不上。因此不折算、不返还金币，也不补收金币。

清空后 `readGrowth()` 得到「拥有节点数为 0」，返回 `{ levels: 全 0, spent: 0 }`：既没有保留下来的强化，也没有可以返还的金币账本，免费重置不会因为旧档产出金币。玩家从链头重新开始购买；此后重置仍按当前链的价格全额返还真实支出。

清空只作用于强化数据，金币余额、已解锁角色与角色选择、任务、成就、生涯战绩都不受影响。

**需要产品决定的迁移点：** 旧金币没有服务端来源账本，无法同时保证全部原额直接用于强化以及新榜单的可信公平。推荐方案是保留旧余额及其消费体验，标记迁移来源；使用迁移资金的强化记录进入同版本成长榜并显示迁移标记，避免把该榜宣传为严格公平竞技。若后续需要公平排名，再为同一冒险提供固定强化预算的比较规则。

旧余额首次迁移必须幂等、绑定新档案，不能靠换标签页重复导入。保留本地原档备份；读取时展示保留的余额与外观，不自动删币，也不根据不可信余额授予竞技证明。浏览器匿名身份无法完全阻止新建档案或篡改首次导入，真实账户和迁移策略需要另行落实。

### 长局上传先补齐

游戏没有结束时间，但当前服务端拒绝超过十分钟的回放，且有 1 MiB 请求体上限。生存强化可能让更多人碰到这个边界，必须列为正式发布前依赖。

建议分批压缩上传输入，在服务端保留已验证模拟状态、帧序号与对局标识，后续分片只能接续；重复、缺片、乱序都要处理。长回放验证移到有时间和资源预算的工作线程，避免阻塞其他 API。仍保留单片大小、验证并发、空闲回收等限制，不能单纯删除原保护上限。

离线或上传失败保留本机对局，明确展示「待验证收益」，联网补交后一次入账；正式金币不能在失败重试中重复奖励。首版保留原有十分钟及请求体限制，超限继续显示上传失败并保留本机战绩；不声称长局上传已经完成。

## 12. 开发顺序与验收

| 批次        | 实际交付                                                                            | 通过条件                                                   |
| ----------- | ----------------------------------------------------------------------------------- | ---------------------------------------------------------- |
| A：成长底座 | 统一强化配置、价格函数、档案版本、可信钱包/购买/退款/结算、开局快照、旧存档清空说明 | 重复操作不多扣少扣；余额、条件、版本可校验；旧档金币与角色延续 |
| B：基础强化 | 升级入口与页面；生命、伤害、拾取、移速、经验、减伤节点；链按顺序解锁                | 前后端一致；全部乐器吃到应有加成；角色切换没有属性例外     |
| C：生存强化 | 回血、安全等待、自动补盾、计时提示；与现有治疗和护盾协调                            | 下述时序与叠加检查通过；自动补盾不能攒到三层               |
| D：发布准备 | 长局分片与异步验证、强化榜单版本、手机试玩与调参                                    | 超十分钟真实死亡记录可验证；错误可恢复；资源受限；真人通过 |
| E：长期内容 | 满装备尾声卡、进化收藏提示、技巧目标，视数据扩展                                    | 长期有选择；不重新扩张为多款游戏；不靠无限基础数值维持成长 |

本次先交付本地永久强化链及效果，榜单按客户端携带的有界开局强化快照重放，验证战斗结果，不验证购买来源。可信金币与服务端账本属于后续工作。第一版不把互斥天赋树、额外货币或新地图作为前置需求。

### 规则验收

- 回血：受击后第 20 秒首次恢复；间隔 12 秒；护盾受击重置；无敌忽略碰撞不重置；满血清空周期；暂停不推进；死者不恢复；最大生命不能被突破。
- 护盾：三个节点（第 16/24/29 步）的 180/150/120 秒准确，取已购最后一个；只在空盾积累；任意有效受击清空全部补盾进度；拾取后计时清空；盾碎后从零开始；同帧拾取只得到掉落层；总层数 ≤3。
- 叠加：爱心、满血卡、爆发保护、受击无敌、减伤、自动回复和盾在同帧按约定顺序计算，死亡不被随后自动恢复撤销。保留现有拾取时序，在受击判定后再处理周期回血和自动补盾。
- 属性：十种乐器、各终极形态、残留与爆发的伤害提升一致（永久伤害是加在乘区之后的固定值）；移动校验随快照变化；拾取不改变攻击半径；经验不增加金币；不同外观同档案效果相同。
- 链：只能买链上第一个未拥有的节点；跳步购买被拒绝并给出提示；每个节点只能买一次；旧的多级存档读取后为空链，不会凭空产生已购节点。
- 交易：余额不足、未解锁、已获得、双击、跨标签页、并发、旧版本、失败重试、按原支出退款和迁移去重均有验证。
- 长局：10/20/30 分钟对局、断线补传、乱序/重复片段、非法续接、提前结束、死亡后输入与并发验证预算；局内仍允许等级无限提升。

### 平衡与真人验证

固定种子自动对比：无强化（链上 0 步）、新手组合（前几步）、中期组合（链中段）、买满整条链，覆盖六种词缀、十种乐器意向和站桩/简单绕圈/最近怪物躲避三类输入。分别记录真实死亡和达到 300/600 秒上限的截尾结果；不能将后者统计为死亡时间。

新增统计：金币、首次购买、首次进化、生命伤害、有效受击、回血量、各来源盾数量/挡伤次数、满血卡选择频率、等待恢复的时间。现有 300 秒绕圈样例来自旧版八项强化树的采样，只能作为量级参考。原有无强化/低强化/满强化 × 六种词缀 × 站桩/绕圈/躲避共 54 局、600 秒上限，以及满强化站桩 6 局、1800 秒上限的对照见 [恢复平衡验证](recovery-balance.md)，其「满强化」指旧版八项满级，不等于买满这条链，需要在新规则下重跑后才能比较。这不是全部构筑或真人平衡证明；更高移速也会改变拾取和接敌轨迹，收入并不保证逐样例单调上升。

首轮目标：新手每一到三局能沿链推进一次有感知的节点；只买到前几步的玩家仍能碰到精英和第一 Boss；买满链后站桩不能在全部词缀下无限存活；链上的生存与伤害节点都有实际优势。若站桩能由掉落和满血卡持续维持，优先调整自动恢复/补盾参数和其协同，再评估现有治疗，不直接删除用户要求的满血卡。

至少邀请新手与熟练玩家各 5 人，在手机触控与电脑各完成多局。检查首次失败是否知道下一步、自动回复是否可理解、盾是否清楚挡住一次攻击、链上加成是否让走位仍然重要、竖链在手机上是否读得懂。前 15/30/60 分钟的购买数量、死亡时间分布和推进位置，再决定价格与回复参数。

当前确定推荐：29 个单级节点组成一条全局链、按顺序解锁、加成全部为固定数值、八秒安全期加十二秒回血周期、空盾 180→150→120 秒补一层且受击重计、免费局间重置，旧的多级强化存档直接清空且不折算。需要实施阶段验证的事项：实际推进速度、防御叠加后的长局难度、旧金币迁移策略，以及可信成长和长局上传底座。
