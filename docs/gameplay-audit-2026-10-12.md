# 小游戏交互、可玩性与布局检查（2026-10-12）

本次检查当前工作区代码，不代表线上版本；只新增本报告，未修改游戏源码。按照 `ui-guidelines.md` 检查，结合三个并行只读审查、确定性规则模拟和浏览器页面实测。

## 范围与验证边界

- 浏览器检查尺寸：320×568、390×844、844×390；覆盖开始、角色商店、战斗、升级、暂停、主动结算。
- 使用临时副本、独立端口和临时数据库，未向线上排行榜提交测试成绩。开始检查时 `PermanentTree.tsx` 缺少闭合标签，副本只补齐该标签用于页面验证；检查期间其他进程已修复工作区该错误，末次验证以最新工作区为准。
- 末次 `npm test`：50 个测试文件、437 个测试通过；`npm run lint`、`npm run build`、`git diff --check` 通过。测试通过不等于下述跨组件交互已覆盖。
- 浏览器模拟尺寸不能代替 iOS/Android 真机触控、浏览器工具栏、安全区和设备性能验证；没有把未经测量的卡顿作为结论。
- 免密昵称登录、本地金币账本、20 分钟回放上榜上限和历史版本混合总榜已有产品约定。本报告不把这些约定本身归为程序错误。

## 优先修复：成绩与进度闭环

### 1. P1：暂停页“结算上榜”生成的成绩无法通过回放

位置：`src/pages/MusicFarm/index.tsx:348–365`、`src/features/farm/rules.mjs:1923–1938`。

触发：生命仍大于零、有得分时暂停，点击“结算上榜”，上传本局成绩。

客户端只把最终状态的生命强制改为零，回放日志没有主动结束动作。服务端重放后玩家仍存活，`state.hp > 0` 导致拒绝。确定性模拟：39 帧、40 分、结束前生命 88，`replayFarm` 返回 `null`，服务端校验失败。这个入口还被用作接近 20 分钟时保住成绩的办法，因此会影响长局玩家。

建议：把主动结束记录为双方共用、可验证的回放动作；保留正常战斗帧，不仅修改本地生命。验收应覆盖短局主动结算、18–20 分钟主动结算、自然死亡，以及伪造终止动作。

### 2. P1：结算后换角色会使本局重试上榜失败

位置：`src/pages/MusicFarm/index.tsx:1417`、`src/pages/MusicFarm/FarmBoard.tsx:100–112`、`src/features/farm/rules.mjs:1943–1966`。

触发：游客完成一局 → 商店切换已拥有角色 → 登录上传；或首次上传失败 → 换角色 → 重试。

提交使用当前 `profile.selected`，本局 `FarmRound` 没有冻结开局角色。服务端用新角色的起始武器重放旧对局，战斗结果不同。模拟自然死亡局：吉他角色 537 帧、28,430 分，原角色校验通过，替换为鼓手后失败。

建议：开局冻结角色 ID 并存入本局记录；榜单、分享和角色展示读取本局快照。换角色只影响下一局。验收应覆盖换角色后的延迟提交和失败重试。

### 3. P1：恢复云端会直接丢弃正在玩的对局

位置：`src/features/auth/AuthGate.tsx:284–307,345–351`。

触发：对局或结算期间出现云端存档冲突，点击账号栏“恢复云端”。

该按钮只检查 `busy`；处理函数立即 `setGameVisible(false)` 卸载游戏，成功或失败后都重建游戏。正在玩的局、未上传的结算均会丢失，且没有放弃本局的确认。正常账号切换已有 `runActive` 延后机制，这条路径未遵循。

建议：恢复延后到返回开始页，或明确确认放弃本局后执行；恢复网络失败也应保留原对局。验收覆盖战斗、升级选择、结算未上传三个阶段。

### 4. P2：登录已有账号后，成长显示仍可能停留在游客数据

位置：`src/features/auth/AuthGate.tsx:58–87,235–245`、`src/pages/MusicFarm/index.tsx:143,175–188,197,445–467`、`src/utils/accountStorage.ts:101–108`。

任何昵称登录都走 `accept(next, true)` 保留游戏实例。页面的金币、角色、成就、生涯、任务、最佳成绩来自初次状态；安装账号存档和切换存储作用域没有统一刷新这些状态，现有存档事件监听只重读 `profile`。

影响：提示“进度已同步”，页面却可能仍显示游客钱包、角色、任务或生涯；下一次操作读取的实际账号数据与展示不一致。

建议：身份变更时统一重新加载全部成长状态，单独保留待上传本局，而不是把所有游客界面状态一起保留。验收使用游客和已有账号的不同金币、角色、任务、生涯数据。

### 5. P2：较大的合法游客存档会阻止登录

位置：`src/features/auth/AuthGate.tsx:235–236`、`server/auth.mjs:115–127`。

登录携带全部游客成长，但 `/login` 请求额度只有 16 KiB，`/register` 才允许成长额度加 16 KiB；当前免密入口统一调用 `/login`。模拟 365 条正常每日最佳成绩：存档校验合法，请求 17,551 字节，返回 413“账号请求过大”。此类用户无法通过正常入口迁移到账号。

建议：统一携带成长的登录与注册额度，按已有成长校验器限制内容；或只在确需迁移时传成长快照。验收使用超过 16 KiB、低于合法成长上限的正常存档。

### 6. P2：存储失败和离线同时发生时，到账反馈会误导玩家

位置：`src/utils/accountStorage.ts:101–108,154–163`、`src/features/auth/cloud.ts:35–36`。

账号存档写入本机失败时退到内存 Map，但上层忽略持久化失败，仍按保存成功发放金币、更新任务。若云端也离线，刷新就会丢失新增成长；提示“进度在本机”没有体现仅在内存的状态。

建议：区分仅内存、本机持久化、云端保存；同时无法落盘和联网时，应给出准确且可恢复的反馈。保留奖励 ID 去重，恢复后补存而非重复发放。

## 战斗操作与效果一致性

### 7. P2：点击爆发等按钮后，键盘走位失去焦点

位置：`src/pages/MusicFarm/index.tsx:1137–1198,1287–1302`。

键盘事件仅绑定战场，且要求 `event.target === event.currentTarget`。点击爆发或静音后焦点在按钮上，WASD/方向键不会到达战场处理器，需要重新聚焦战场。这是源码可确定的焦点路径，尚未完成真机键鼠混用验证。

建议：战斗按钮执行后恢复战场焦点，或在游戏作用域处理快捷键并排除输入框与弹窗。验收应交替使用键盘走位、鼠标爆发、静音和暂停。

### 8. P2：主唱进化承诺攻击八只，实际只攻击六只

位置：`src/features/farm/rules.mjs:455,1208`。

配方声称“一次追击八只怪，全场降下暴击音雨”，实现上限是 6、范围是 52。隔离放置八只范围内怪物，仅产生六次 `rain`，另外两只未受伤；普通 Lv.5 本身已有六目标，进化未提供宣传的目标数增加。

建议：明确最终玩法数值，再统一说明与实现；验收应直接对比进化前后的命中数量和范围。

### 9. P2：键盘流的怪物出生距离与真实攻击范围不一致

位置：`src/features/farm/rules.mjs:587,1346`、`src/features/farm/world.test.mjs:67`。

满级键盘与踏板时，`farmReach` 为 79，实际星浪半径为 56，最低生成半径为 93。怪物要额外靠近至少 37 单位才进入星浪，超出生成逻辑希望预留的 14 单位，拖慢收割与经验节奏。现有测试只固定预期 79，没有对照实际攻击半径。

建议：出生距离与攻击使用同一范围计算，结合混合构筑验证怪物接近速度和获取经验节奏。

### 10. P3：组合技“全部伤害”说明不覆盖鼓手余音

位置：`src/features/farm/schools.mjs:159`、`src/features/farm/rules.mjs:996`。

“全场安可”显示全部伤害 +8%，但余音绕过组合倍率，隔离测试触发前后仍每跳 6。余音不吃普通命中加成已有明确机制，问题在组合说明。

建议：改为符合实际的“命中伤害”说明，避免让玩家误判主流派收益。

## 布局与信息可达性

### 11. P2：常规手机结算页删掉了本局复盘入口

位置：`src/pages/MusicFarm/style.css:2880–2941`、`src/pages/MusicFarm/index.tsx:1369–1371`。

390×844 实测中，构筑、时间曲线、每日目标、本局新成就全部 `display: none`，并非仅矮屏处理。顶部成就墙可查看长期成就，却不能恢复本局曲线或构筑；结算后也没有暂停入口查看本局。页面下方仍有明显空白。

建议：保持单屏主结算，增加紧凑的本局摘要或复盘入口；保留任务达成与成就解锁的最小反馈。避免完成成长却没有感知到奖励。320×568 的分享按钮也被隐藏，可考虑放入复盘/分享入口。

### 12. P2：横屏暂停页仍需要滚动

位置：`src/pages/MusicFarm/index.tsx:1478–1537`、`src/pages/MusicFarm/style.css` 的 `.farm-dialog` 规则。

844×390 实测：月亮装饰、标题、继续按钮、结算/特效占据上半页，构筑、任务、重新开始在滚动区。游戏叠加层单屏规范未达成；“结算上榜”和“特效 开”作为相邻文字按钮，视觉上缺少分隔。

建议：矮屏暂停隐藏装饰、缩减次要信息，核心动作固定在一屏；构筑与任务采用明确入口而非全部展开。

### 13. P2：部分触控目标仍小于规范

位置：`src/pages/MusicFarm/CharacterShop.css:612–621`、`src/pages/MusicFarm/FarmBoard.css` 的刷新按钮样式。

实测横屏商店返回为 38×38；320×568 开始页排行榜刷新宽约 33.68、高 40，均低于 40×40。另登录返回、错误重连缺少一致的最小尺寸约束，应纳入同轮测量。横屏暂停按钮实际为 40×40，早期 CSS 的 36×36 被后续规则覆盖，不列为问题。

建议：为可点击目标统一设置最小宽高，压缩装饰而非点击区域。验收按最终计算尺寸，不能只看某一条 CSS。

### 14. P3：帮助按钮的文案与动作不一致

位置：`src/pages/MusicFarm/FarmHelp.tsx:77–79`。

“懂啦，开战”只调用关闭帮助。从开始页或结算页打开帮助，点击并不会开始游戏。

建议：改为“返回”，完整语义放入 `aria-label`。

## 可玩性建议与测试缺口

以下是设计风险，应通过玩家体验和更多策略验证，不能当作人类玩法强度的最终排名。

1. **角色售价与初期生存体验差距大。** 使用项目现有 `simulateFarm`、零永久强化、相同 dodge 策略、所属流派升级、自动爆发、300 秒上限：当前日键盘手 48.38 秒、主唱 66.81 秒、贝斯 77.69 秒死亡，吉他与唱盘均存活到上限。再对六种词缀代表种子比较，吉他 6/6 存活到 300 秒，主唱 2/6、键盘 1/6。键盘售价 4,800、吉他 600，可能出现攒钱解锁后更难玩的体验。建议优先比较首个 Boss 前的伤害、经验和生存窗口，而不是只调售价。
2. **最后一个芯片槽缺少不可逆选择反馈。** `rules.mjs:756` 满五芯片后无法获得新芯片；鼓满级但五槽被 `tempo/magnet/lucky/sustain/delay` 占满，就永远无法获得音箱并进化。建议在最后槽的选择展示配套关系与当前无法完成的进化，或提供有限替换机制。
3. **买角色前难以判断玩法。** `CharacterShop.tsx:79–83,143–146` 主要提供姓名、价格和流派名，缺少一句可比较的攻击特点。建议在当前预览处显示“环绕音刃”“延时音爆”等短特点，帮助玩家决定金币用途。
4. **永久链远期节点占据导航距离。** 免费重置在全部 200 步之后。只买了几步也要穿过大量未解锁内容才能找到；建议把重置移到固定工具区，或折叠远期节点。节点名称/价格不能替代对累计属性的直观反馈。
5. **低强化平衡检测实际没有测到低强化。** `scripts/check-farm-balance.mjs:147` 的 `low` 使用旧 `vitality/armor/regen/shield` 键，而 `permanent.mjs:88` 只认 `step-N`，归一化后与零强化属性相同。建议用连续前 N 步构造真实低强化档，并增加角色基线比较。

## 建议处理顺序

1. 先修主动结算、冻结本局角色和恢复云端丢局，确保玩过的成绩可提交、对局不会意外消失。
2. 再修账号状态刷新、登录额度和存储反馈，确保成长展示与实际存档一致。
3. 修键盘焦点及武器效果一致性，补针对真实问题的回归测试。
4. 优化手机结算反馈、横屏暂停和触控尺寸，再通过真机验证。
5. 更新平衡模拟，验证角色成长窗口和芯片决策；区分操作难度、风格差异与纯数值弱势。
