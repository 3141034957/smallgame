# 软糖乐队 · 声音探险

首页打开即进入可玩的场景，首次游玩先完成「点亮声音，让小兔唱起来」：三行三列的小地图只突出下一步目标，点击有手势提示的发光格子，三次采集后，第四次点击自动接到小兔。每次点击都有即时声音和进度反馈，完成后可以直接保存第一首小曲，或继续同一段旅途。引导状态保存在当前浏览器，可跳过；后续游玩直接进入完整地图。

完整玩法是围绕音乐进行路线规划的回合探险。玩家带奶糖在五行五列小岛上行走，沿途采集四种声音，接回三位伙伴，再回营地开启野餐音乐会。没有反应速度要求和倒计时；剩余脚步、声音资源和路线决定结果。

## 音乐与玩法的联系

四种可采集植物分别是咚咚蘑菇、泡芙花、布丁浆果和啾啾风铃，对应鼓、键盘、贝斯和主唱。采集时立即发声，采集顺序和位置决定旅途谱面的音色与音高；背景循环会随采集增加音符。伙伴入队后加入对应的合奏声部。旅途结束可重复试听，并通过链接把完整行动记录寄给朋友。

音乐资源同时承担任务与技能成本。走到伙伴身边时，资源足够就自动消耗一颗对应声音加一颗任意声音（允许同种），邀请伙伴入队。四种旅行魔法默认收起，玩家按需展开；消耗口袋里的声音可以使用：

- 蹦蹦捷径：消耗一颗鼓声，下次移动可以抵达曼哈顿距离不超过两格的位置，只消耗一步。
- 花开双倍：消耗一颗键盘声，下一处未收集植物产出两颗资源，并增加对应采集得分。
- 午睡补给：消耗一颗贝斯声，恢复三步，每局一次；剩余零步时也能使用。
- 风的口袋：消耗一颗主唱声，一次收集四周相邻格子的全部未收集声音，不移动位置。

连续采集三个不同声部会触发音乐花火，+60 分、恢复一步，然后清空本段组合。空地、移动与使用技能本身不打断组合，收集音符的顺序才决定花火。

## 地图、通关与计分

三座岛初始脚步分别为 18、17、16。每移动一次消耗一步；走过的植物不会重复产出。邀请伙伴 +220 分，普通采集每颗资源 +40 分。接齐三位伙伴并回到营地后自动开音乐会，额外 +400 分，剩余每步 +20 分。玩家可随时收起旅途并保存部分成果。

接回一位伙伴为一星、两位为二星；三位伙伴在营地开音乐会为三星。收集一星解锁云朵港湾，三星解锁月亮森林。每座岛只保存历史最高分与最高星级，不能重复刷同一成绩累计星星。

北京时间的日期和小岛 ID 共同生成地图。每天布局会变化，同一天同一座岛的地图一致。固定几个声源保证基础通关路线存在；测试验证多日期与全部岛的可通关性。分享旧日期的链接会还原当时地图。分享链接可以直接进入指定岛，让朋友参与同一条航线。

## 分享与排行榜

自动邀请与自动结算仍写入明确的行动记录，使用同一套权威规则核验，不改变服务端校验条件。分享编码保存每次移动、邀请、施法和结束动作。朋友打开链接，在首页可以试听原旅途，并从头挑战同一地图。试听不会自动发布朋友的成绩，也不会改变本机星级。HTTP 剪贴板不可用时提供手动复制链接。

`GET /api/island/leaderboard?island=picnic&day=2026-10-03&playerId=...` 与 `POST /api/island/score` 提供独立航线榜，按日期、小岛分别排名。玩家主动填昵称上榜。服务端使用 `src/features/island/rules.mjs` 从起点重放全部动作，检查移动范围、脚步、技能成本、邀请条件、重复采集和总分；不能仅通过传递高分数字上榜。匿名客户端仍可构造合法行动序列，此榜用于轻量路线挑战，没有账号或服务端实时竞赛防作弊。

排行榜复用现有 SQLite 存储，在 `melody_scores` 使用独立的 `island:<日期>:<小岛>` 键及 `explore` 模式，不影响原节奏或跳跃排行榜。排序依次为得分、探索率、音乐花火、首次达成时间。显示前 50 名与个人名次。昵称和匿名身份复用现有浏览器存档，换设备或清除数据会产生新身份。

## 界面与兼容

默认首页 `#/` 是声音探险；`#/rhythm` 保留节奏舞台、自由排练与原排行榜；`#/echo`、`#/mochi`、`#/shop` 保留原有游戏。旧节奏 `song` / `mix` 根路径邀请链接会自动跳转到节奏舞台，旧花房邀请继续兼容。

植物、营地与地图是代码绘制的 SVG/CSS，乐队角色复用现有 SVG，首页复用已有 AI 生成插画。音色由 Web Audio 合成，无外部歌曲或音频 API。支持点格子、键盘方向键、减弱动画设置、键盘焦点与帮助对话框。切换标签页停止声音，不消耗脚步。390×844 手机首屏完整显示目标、引导地图与点击提示，完成奖励和继续按钮也在屏幕内；完整地图可完整显示。魔法入口和返回地图按钮方便往返操作。

## 本地与部署

开发运行 `npm run dev` 和 `npm run dev:server`；生产运行 `npm run build`、`npm start`，仍使用 3001 端口。服务器依赖两套共享规则文件，部署时保留完整项目，包含 `src/features/island/rules.mjs` 与 `src/features/melody/rules.mjs`。升级前备份 `server/data`；可用绝对路径的 `DATA_DIR` 指定其他目录。

实现与验证在本地分支 `feat/mochi-melody`，没有自动同步到公网 Ubuntu 实例。
